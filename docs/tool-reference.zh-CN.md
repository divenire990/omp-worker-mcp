## 1. 单任务委托工具集

| 工具名称 | 工具定位 | 用途与运行行为 |
| :--- | :--- | :--- |
| `omp_run_compact` | **高级封装** *(推荐)* | **单任务委托首选入口**。在单轮对话中委托单个任务并在 `wait_seconds`（默认 60 秒）内等待结果，直接返回压缩的执行摘要。 |
| `omp_delegate` | **底层分发** | 异步创建后台 Worker 执行编码任务，立即返回唯一 `job_id`，适用于解耦的分步执行流。 |
| `omp_wait` | **底层等待** | 等待正在运行的后台任务直至终态，或轮询至达到 `timeout_seconds` 超时时间。 |
| `omp_result` | **结果检视** | 获取指定 `job_id` 的完整尝试历史、标准输出/错误日志、修改产物及解析后的结构化结果信封。 |
| `omp_continue` | **监督纠错** | 向失败、阻塞或未完全满足验收标准的任务注入监督指导（`feedback`），在同一会话中发起新一轮尝试而无需丢失上下文。 |
| `omp_cancel` | **执行控制** | 向运行中的任务发送取消请求，优雅终止该任务及其派生的子进程树。 |

## 2. 批量任务与 DAG 编排工具集

| 工具名称 | 工具定位 | 用途与运行行为 |
| :--- | :--- | :--- |
| `omp_run_batch_compact` | **高级封装** *(推荐)* | **多任务 DAG 工作流首选入口**。校验拓扑依赖与所有权冲突，按 `max_parallel` (1–10) 并发池调度执行，并在 `wait_seconds` 内等待进展或全部完成返回汇总结果。 |
| `omp_wait_group` | **底层等待** | 等待异步批量任务组的执行推进或全部完成。 |
| `omp_cancel_group` | **执行控制** | 取消批量任务组中所有正在运行及处于等待队列中的任务。 |

## 3. 任务安全与所有权约束

为保证 Agent 在并发与复杂场景下的确定性与零冲突执行，`omp-worker-mcp` 实施以下三项安全与所有权机制：

### 1. 写入与只读隔离
- **批量任务项（`omp_run_batch_compact`）**：批量 DAG 中的任务项通过 `access` 声明访问模式（`write` 或 `read_only`）。`write` 任务项必须通过 `ownership` 参数明确声明其拥有修改权的工作区文件路径或目录，声明的边界将作为提示约束注入给 Worker；`read_only` 任务项不声明写入范围，并在 Worker 提示中作为只读约束提供。
- **单任务委托（`omp_run_compact`）**：单任务工具不接收 `access` 或 `ownership` 参数；只读与不修改文件的意图必须直接在任务的 `goal` 与 `acceptance` 验收标准中表述。
### 2. DAG 冲突与重叠校验
- **互斥所有权**：服务端在批量任务组提交时校验并拒绝并发重叠的写入范围。
- **串行化依赖**：需要修改相同路径的任务必须通过 `depends_on` 显式声明线性的先后依赖关系。
- **提交期拓扑验证**：服务器在提交时即对任务图进行完整静态分析，若存在循环依赖或所有权冲突则在启动任何 Worker 前直接拒绝。

### 3. 结构化校验信封约定（`OMP_WORKER_RESULT`）
所有子任务均被要求在最终输出中遵循标准化的结构化结果信封格式：

```text
OMP_WORKER_RESULT
{"status":"completed|blocked","summary":"简要工作总结","artifacts":[{"path":"相对路径","description":"变更说明"}],"verification":["测试命令及执行结果"],"remaining":["未完成项或阻碍原因"]}
```

- **`status`**：所有验收标准均达成且经测试验证时为 `"completed"`；存在外部阻塞时为 `"blocked"`。
- **`summary`**：对已完成工作的简明精炼描述。
- **`artifacts`**：所修改或新建的相对文件路径及说明清单。
- **`verification`**：具体执行的测试命令、场景校验及其观测结果。
- **`remaining`**：若任务未完成，列出具体的遗留项或阻塞原因。
